# 024 复现用例（本地测试入口）

Agent 为一个已报告的 case 写复现脚本时，脚本留在本机、不进仓库。这个文档定义这些脚本怎么放、面板怎么列出和运行它们，以及"在一次编辑器启动里反复跑"靠什么成立。

## 为什么

复现脚本的价值在于**再跑一次**：改完代码要重跑，人想自己看一遍，同一个边界要换参数扫几轮。之前这些脚本散在工单目录里，只有写它的 agent 知道怎么跑；人想触发就得重新开会话、重写一遍，或者重启编辑器跑一次性的命令。

面板的**复现用例**卡片把这件事变成一个入口：列出本地用例，点"运行"在已经打开的编辑器上跑，跑完打开报告；再点一次就是再一次运行，编辑器不重启。

## 目录与 case.json

用例目录：

- 配置了编辑器工程（设置 › 执行 › 编辑器工程）时：`<工程目录>/Saved/ReproTests/`，跟着工程走，`Saved` 本来就不入库；
- 没有配置时：`<stateDir>/repro-tests/`，面板始终有一个可以列出的地方。

卡片在标题下显示当前目录，人不用猜。

一个用例一个文件夹，文件夹名就是用例 id（列表里的稳定标识）。文件夹里放 `case.json`：

```json
{
  "name": "急转：镜头转动时的滑动",
  "description": "站定后转镜头，采样角色朝向与位移",
  "command": "py -3 run.py",
  "report": "reports/latest.html",
  "timeoutSeconds": 600
}
```

| 字段 | 说明 |
| --- | --- |
| `command` | 必填。在用例文件夹里用平台自带的 shell 执行，脚本、夹具和产物都可以放在旁边 |
| `name` | 列表显示的名字，缺省用文件夹名 |
| `description` | 一句话说明复现什么 |
| `report` | 跑完要打开的文件，相对用例目录；跑完确实存在时才显示"报告" |
| `timeoutSeconds` | 允许跑多久，10 秒–2 小时，缺省 20 分钟 |

`case.json` 缺失、写坏或字段不合法时，这个用例仍然列出来并标"配置有误"及原因，不会静默消失；`report` 写成绝对路径或 `..` 跳出用例目录会被拒绝。

## 运行规则

- **一次一个**：面板同一时间只跑一个用例，按钮变成"停止"；再点别的用例会等这次结束。
- **本地进程**：命令由宿主进程启动（和编辑器作业同一套进程/日志方式），输出写 `<stateDir>/repro-logs/<runId>.log`，页面显示最后几 KB；"输出"按需读取，最多 32 KB。
- **超时**：超过 `timeoutSeconds`（缺省 20 分钟）由宿主结束进程并记为失败。
- **记录**：状态、退出码、最后一行输出和报告写入 `KV.repro.runs`（最多 40 条），宿主重启后已结束的运行仍可查；重启时还在跑的会被停掉并记为"被中断"，因为它的输出已经丢了。
- **不阻塞编辑器调度**：agent 或宿主的编辑器作业占着编辑器时，卡片拒绝运行并说明原因，等它让出（同一页的"编辑器调度"卡）再跑；人自己开着的编辑器不会被面板当作冲突。
- **夜间自动重放**（`docs/029`）：已交付、等一个人做本地验收的工单，如果验证包点名了一个可运行的 case，宿主会在 20:00–08:00 的闲时窗口里自己跑一次（一次一个、一晚默认一个、只在机器闲下来且没有 agent/宿主作业占编辑器时）。夜里的运行也进同一份 `KV.repro.runs`，`origin: "night"` 标明来源，报告和退出码照旧显示在验收页的复现入口；它不发消息，也不替人判定。

### 一次编辑器启动里反复运行

用例脚本连的是**已经开着**的编辑器（UnrealBridge、ue-mcp 或引擎 MCP），面板从不重启它，所以：

1. 打开编辑器（人开，或 agent 通过调度拿租约开）；
2. 在面板里点用例，脚本在编辑器上重放输入、采样、写报告；
3. 再点一次就是下一轮；换一个用例也是同一个编辑器。

只有确实需要冷启动编辑器的用例才自己启动进程，那种用例按普通本地进程计，不会因为面板而得到额外保护。

## 报告

报告通过 `/orchestrator/repro/file/<runId>/<相对路径>` 打开，路径只能落在该运行的用例目录里：

- HTML 和 SVG 以 `sandbox allow-scripts` 的源提供：报告里的脚本能跑，但拿不到面板的同源管理接口；
- 报告引用用例目录里的相对图片、样式可以直接加载；`file:///` 绝对路径不行，产物请写在用例目录里；
- 其他类型（PNG、JSON、Markdown、日志、PDF 等）按内容类型打开或下载。

## 写入方（worker）

验证脚本能被人重跑时，在脚本旁边放一个 `case.json`，把入口命令和报告路径写清楚；脚本、夹具和产物都留在本地用例目录，不进仓库。验证包里写明用例名与目录，人就可以自己在面板里跑，不必重新开会话。

## 验收页上的复现入口

交付单的验收页直接带出 worker 的验证包（四段：版本与前置 / 复现步骤 / 预期与证据 / 待你判断）与复现用例，人不用先去编辑器页找：

- 页面按验证包文本里出现的用例目录名匹配本地用例（例如 `Saved/ReproTests/20261105-183235-c75bbc4c_ZZAttack05` 对应目录名 `20261105-183235-c75bbc4c_ZZAttack05`）；包内没有目录名时，退回到「目录名含工单 id 前 8 位」。
- 匹配到的用例显示命令、最近一次运行、退出码和报告链接，并带一个「运行用例」按钮：它与编辑器页的卡片调用同一个 `POST repro/run`，一次只跑一个，编辑器被 agent 或宿主作业占用时按钮禁用。
- 匹配不到时，页面说「这次交付没有可运行的复现用例」，同时保留 worker 写的复现步骤，并给一个到编辑器页复现用例卡的入口。
- 这个匹配只读、不改 `case.json` 格式；验证包仍由 worker 自己写，面板不替人重放「版本与前置」里的应用测试文件、构建、revert 等动作。

## 与 A/B 对照的关系

这个入口只负责把一次运行变成可重跑、可观察的用例。要对照改动前后，用 docs/026 的 A/B harness：同一个 case 在 baseline 与 fix 两臂各跑一次，`case.json` 的 `command` 指向它，`report` 仍由这张卡片打开。本文只定义单个用例的目录与运行规则，不重复那份 A/B 清单。

## 边界

- 只运行用例目录里列出的用例：请求只带用例 id，不接受路径或命令。
- 一次一个、有超时、退出码即结论；不因为报告好看就当作通过。
- 报告只读；面板不写、不改、不清理用例文件。
