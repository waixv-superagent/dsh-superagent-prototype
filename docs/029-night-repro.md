# 029 — 夜间复现队列：把已交付的 case 在夜里先跑完

> 2026-11-07 · 由自动化代理（大肥鱼）实现，依据 11-05 复盘「闲时池最小队列」与 11-06 复盘 P2 项的验收：
> 夜间跑完 1 个 repro case。本文说明这一版落地的窗口、门、数据与边界；没做的部分写清楚，不当作已完成。

## 0. 一句话

交付完、等一个人做本地验收的工单，如果它的验证包点名了一个本地复现用例，宿主会在 **20:00–08:00** 的
闲时窗口里自己把那个 case 跑一遍：一次一个、一晚最多一个、只在机器真的闲下来时启动；跑的过程和结果
都不发消息，第二天人打开工单时，已有的「复现用例」卡片里已经有一次跑完、可判的运行。

## 1. 为什么是「先跑完」而不是「再发一条提醒」

[025](025-reproducible-verification.md) 的流水线最后一步是 **idle**：重活进闲时池，人坐下时只收到
「跑完、可判」的结论。而 [024](024-repro-tests.md) 的复现用例一直只由人点击触发：白天点会占着人正在
用的编辑器，夜里又没有入口。结果「等人验证」的单到了早上仍然只有一个命令和一段步骤，人还得自己开编辑器
重跑一次。

夜间队列补的是这一格：把「跑一次」从人的动作变成闲时动作，但不改变 evidence 的判定权——退出码、报告和
输出仍然只是证据，过不过由人判（[012](012-gates-and-cards.md) 的 P4.5）。

## 2. 什么时候会跑

启动要同时满足：

| 条件 | 说明 |
| --- | --- |
| 窗口 | 本地时间落在 `executor.idle.repro.window`（默认 `20:00–08:00`，跨午夜）。白天、午间、工作时间都不启动 |
| 闲时 | 复用 [019](019-priority-and-idle.md) 的五信号里的队列、容量和护栏：没有可跑的 P0/P1、至少一个 worker 槽连续空闲 `slotFreeMin`、未暂停且没有未解决的 P0；`level` 不存在时不跑 |
| 编辑器 | 没有 agent 或宿主作业持有编辑器租约；人自己开着的编辑器不算冲突（与 [024](024-repro-tests.md) 的运行规则一致） |
| 一次一个 | `ReproRunner` 里有任何一次运行在飞时，队列不启动第二个 |
| 名额 | 同一「夜」最多 `perNight` 个（默认 1）。夜按窗口开始的那一天命名，所以 02:00 属于前一天晚上，不会在新的一天再拿一份名额 |
| 候选 | 未结束、`verification.state === 'pending'`（等本地验收）、验证包非空、且验证包点到的一个 case 目录可运行；同一张单只跑一次 |

候选按进池时间从早到晚取，避免老单被新交付挤掉。台账里「P1 每日两批」的注意力批次是另一件事，不在本文。

## 3. 跑完之后

- 运行记录进 `KV.repro.runs`（与人工点击共用一套记录，`origin: 'night'` 标明来源），报告继续由
  `/orchestrator/repro/file/<runId>/<相对路径>` 打开。
- 工单上写 `idle.repro { caseId, runId, state, night, startedAt, endedAt?, exitCode?, summary?, report? }`；
  工单卡片的 `idle` 字段带上它，看板与 `orchestrator_read` 都能读到「这张单昨夜跑过什么、结果如何」。
- 宿主重启时 `ReproRunner` 把失联的运行标为 `interrupted`，队列在下一个心跳把工单上的 `running` 一起收敛，
  不会留下一张永远「正在跑」的单。

## 4. 静默是结构，不是约定

`NightRepro` 的宿主依赖只有工单库、`ReproRunner`、闲时判定和编辑器占用：没有 `Outbox`、没有 Session
prompt、没有 domain event。它写不进一条 IM 或一张卡片，也不会唤醒主 Session。夜里只有工单和运行记录
发生变化，早上由人的注意力入口读取，这与 [027](027-idle-analysis.md) 对只读分析的静默要求一致。

## 5. 配置与边界

```json
{ "executor": { "idle": { "repro": { "enabled": true,
  "window": { "from": "20:00", "to": "08:00" }, "perNight": 1 } } } }
```

- `enabled: false` 恢复「只有人点击才跑」的旧行为；`perNight` 可调到 10，但共享编辑器一次只跑一个，
  实际是串行的。
- 窗口是独立设置，不改变 [019](019-priority-and-idle.md) 的 L1/L2/L3 深度：20:00 进入复现窗口时，
  闲时深度仍按既有窗口与人的安静程度判定，队列只是多了一个「机器空着时才可以做」的任务。
- **明确没做**：早间摘要（`docs/019` 的未做项）；跑失败后自动重跑或自动改优先级；跨多张单的失败聚类；
  夜间自动打开/重启编辑器（[024](024-repro-tests.md) 的用例连的是已经开着的编辑器，需要冷启动的 case
  自己启动进程）；把 `origin` 画到面板上（本次只在数据层记录来源，面板继续用现有的运行行）。
- 一旦某张单跑过一次夜间 case，队列不会在之后的夜晚自动再跑它；重跑仍由人点击，或由新的交付产生新工单。
